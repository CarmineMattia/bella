# Known limitations — 0.1.0-alpha.3

- **Local mode.** Local sessions share SQLite on one Linux computer. Use the optional hub for separate computers; P2P transport, end-to-end encryption, private group invitations and Android remain future work. Do not put this WAL database on a network filesystem to simulate networking.
- **Local-mode names.** Per-name drafts, read state, agent rooms, pins, and task history are convenience separation, not authentication or privacy enforcement. Someone with database access can read or change them.
- **Reviewable commands.** Literal terminal control characters (except newline/tab) and bidirectional formatting controls are rejected before approval. Use printable shell escapes instead when a command needs those bytes.
- **Owner approvals, ordinary Linux permissions.** Shell commands run as your user. A working directory is not a sandbox. Completed changes and background jobs cannot be rolled back by Stop. Closing forcibly may leave an approved owner command running under its 20-second timeout.
- **Guest shell is not a sandbox.** When *Guest tools* is set to `shell`, approved guest commands run as your Linux user in a dedicated folder, with a scrubbed environment, a 1 GiB address-space cap, a process-count cap and lowered niceness. They can still read files outside that folder, use the network, and start long-running work (there is no time limit; use Stop). Stronger isolation — bubblewrap, Linux namespaces or a dedicated user — is future work.
- **Installed inference required.** The package contains no model weights or llama.cpp executable. Automatic startup targets local HTTP `/v1` endpoints and uses an explicit installed GGUF. There is no GPU/hardware detector, model download, API-key authentication, or remote deployment manager.
- **One active request per app instance.** Two independent instances using the same name can each issue a request. There is no cross-instance task lock or automatic scheduling.
- **Recovery is manual.** Crash recovery records interruption and saves the last checkpoint. It never replays work or approves a pending command. Activity shows the latest 50 records; the underlying database retains older tasks. Inspect approved-command effects before manually asking again.
- **Checkpoint and memory limits.** The UI checkpoints streaming text approximately every refresh; the last unflushed bytes can be lost on a crash. Older history loads in 200-message pages, with loaded messages held in memory until changing chats or jumping to the latest. Very large loaded histories can slow the terminal.
- **Model context.** The agent supplies the latest 24 complete conversation events and has no tokenizer-aware context budget. Very long requests or large command outputs can exceed a configured model context; start a fresh conversation or increase the model context when needed.
- **Text behavior.** Editing is UTF-8 character based rather than full grapheme-cluster based; combined emoji or combining marks may require multiple cursor/deletion steps. Search is ASCII-case-insensitive and exact-case for non-ASCII. The editor displays pasted newlines as separators on its single visible composer line.
- **Terminal differences.** At least 80×24 is recommended. Small layouts avoid crashing, but can clip labels; information dialogs can scroll. Alt+Enter and function keys may be intercepted by a terminal. Slash commands and the mouse provide alternatives. With mouse capture active, some terminals require Shift for native text selection.
- **Presence is local.** F6 shows PID-verified app sessions viewing a room and historical human authors. It is not an authenticated membership list or remote online indicator.
- **Desktop capability scope.** The development build has text chat, approved shell tools, and an approved default-browser launcher when run in a graphical desktop session. It does not expose file-attachment uploads, voice/video, standalone file tools, or desktop-control tools.
- **Packaging scope.** The binary targets Linux x86_64 and is statically linked with musl and bundled SQLite. Python 3.11+ is still needed for the launcher; `sh` and GNU `timeout` are needed for tools. macOS, Windows and ARM packages are not supplied.

- **Pictures are terminal thumbnails.** PNG/JPEG only, up to 8 MiB and 4096 × 4096; stored at 24 × 24 pixels. Truecolor support affects appearance. No remote picture URLs, original image attachments, animation or graphical file chooser.
- **Bot configuration.** Handles are immutable; removing a bot from a chat preserves its profile and history. Local-mode membership is a per-name preference. In hub mode, bot membership is shared and enforced for the owning authenticated account; group access is public. Bots share the configured endpoint/workspace; a model override must be available on that endpoint. Active requests keep their original configuration. No external Telegram integration or automatic agent-to-agent loop.

- **First network alpha.** Hub mode supports separate computers with authenticated accounts, public groups and durable message sync. It has no private group roles, end-to-end encryption, remote online presence, password recovery or production rate limiting. HTTP is plain text; use a trusted LAN, encrypted tunnel or HTTPS. Read [NETWORK.md](NETWORK.md). Bot streaming is local until the reply ends, and bot instructions/workspaces remain device settings.

- **Network timeline order.** The cache preserves local insertion/arrival order. After an offline period, optimistic local messages can appear before older messages received during catch-up. Server receipts prevent duplicate sends, but this alpha does not fully reconcile the visible timeline into server sequence order.
